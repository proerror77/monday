# CEX 云端数据流与重复工作审查

任务：[#1166](https://github.com/proerror77/monday/issues/1166)。审查基线：
`65e8196f6196b89100159d8dd684b439cc44d332`。实际运行证据来自
[#1165](https://github.com/proerror77/monday/issues/1165) 的六组 MLP 对照。

## 结论和实际代价

训练、评估和原生结算已经在 ACK；问题是额外的本机操作把云端已有证据
再次下载，并将下一组实验依赖于这次下载。旧操作说明还把会读取数据的
freeze 描述成本机控制操作。代码内也有重复：Shell 下载结果包后，Rust
结算重新下载同一个包。

本次运行额外下载到工作站的输入为 122,483,126 字节，结果副本为
69,552,997 字节。六个训练/评估容器合计 325 秒，原生 ACK 结算容器合计
46 秒；ACK 完成到本机回读阶段合计约 24 分钟，包括传输及流程等待，不能
全部算作网络耗时。另有约 18 MB 的账本/检查点恢复备份，需保留其恢复用途，
不能一概视为无效副本。

当前运行的补救已在 ACK 只读 Job 复用原有缓存，8 秒生成 435,560 字节报告。
报告 SHA256 为 `da55e9342850a27d94e24a9155dc35e7f4414fa0abb262a4ed956e4288df89bf`，
对象为 `research/campaigns/mlp-training-study/20260913/reports/cloud-summary-v1.json`。
只有该轻量报告回到本机排版。它没有重新训练或评估；这不抹去此前本机传输的历史。

## 逐环节审查

| 环节与实现 | 重复情况与用途 | 本次处置／有效复用条件 |
| --- | --- | --- |
| 发现和物化：`mission_fresh_inputs::prepare` | 重试已有物化输出，可能误被外部驱动重新物化 | 保留现有输入指纹、请求和回执校验后复用；入口限定云端处理 |
| 冻结：`mission_campaign::freeze` | 旧操作在 Mac 下载已有输入以执行冻结 | freeze 在 ACK 原有输入目录执行；Mac 只接收并签署冻结元数据 |
| 提交：`mission_dispatch::admission` | 每次重试读取授权、撤销、账本和 Job 身份 | 保留。这些是当前权限及唯一执行检查，不能用旧成功日志替代 |
| Campaign 输入和多轮训练：`mission_campaign::execute` | 同一 Job 的共享输入下载一次；不同 Campaign 仍各自获取相同输入 | 保留 Job 隔离和逐次 SHA 准入。跨 Job 共享缓存属于独立优化，不能仅因 URL 相同而免校验 |
| 训练、保存和便携推理：`mission_runner` | 训练/保存/加载/便携推理的一致性核验可能再次计算输出 | 保留数值和时间合同核验；报告生成不再增加拟合或预测工作 |
| 发布：Mission、结果包及 Campaign PUT→GET | 生产者自身 PUT 后重新读回 | 保留。这是对象完整性与创建成功证据，不等于独立结算 |
| ACK Shell→Rust 结算 | Shell 已下载 Mission/ZIP，Rust 又下载一次 | Rust 接收 ACK 缓存，独立读取小 Campaign 结果后按其 SHA 验证缓存；缓存缺失/改变直接拒绝，不自动二次下载 |
| Rust 语义重建与持仓会计 | 已有哈希后仍重建因子、模型、回放、试验数和赢家 | 保留。哈希一致不证明收益、身份、holdout 和预算语义正确 |
| ACK→本机重复回读、日志解析 | 私有 Python 重拉 ZIP、重算报告；混合格式日志解析失败又卡住下一组 | 原生结算生成有界报告；工作站只排版，下一组由云端结算/报告回执推进 |
| 报告发布中断 | 已完成模型可能因摘要失败而重启或重下载 | 同一 ACK 缓存、账本结算 SHA 和不可变报告字节恢复，仅补发布/回读 |
| 学习与下一代 | 重试可能重新规划或向另一代移动 | 保留现有学习检查点及完整性记录；本机展示报告不是下一代前置条件 |
| 租约和清理 | 私有桌面守护进程在中断后消失，节点保留标记仍存在 | 新流程使用有期限的 ACK Job；原生控制器期限不超过根授权 Job 秒数及 8 小时。保留原任务期限和按 UID 清理规则；不把桌面 PID 当唯一保障 |

## 修复后的数据路径

```text
OSS / ACK 已有输入 → ACK 物化／freeze → 元数据签名 → ACK dispatch
  → ACK Campaign 训练和评估 → OSS 不可变结果
  → ACK 一份 round-readback 缓存
  → Rust 小结果独立读回＋缓存 SHA＋语义结算
  → 同缓存生成轻量原生报告 → OSS 创建一次＋独立读回
  → 云端下一代或有结论终止
                    └→ 工作站读取轻量报告并排版
```

`model-report.json` 上限 4 MiB，含原生 IC、Rank IC、ICIR、净收益、Sharpe、
适用的 IR 和 MLP 学习/预测诊断；保留原生频率、可用性和分母定义。
请求、Campaign 结果、执行/读取源码及各轮 ZIP 身份都在报告中。
报告复制已经核验的指标，不读取原始数据，不拟合模型，不重放持仓账本，
不解析控制台文本，也不把空仓的零收益解释为获利。

数据入口拒绝非 Linux 主机，防止再次误在当前 Mac 执行；Linux 检查不是 ACK
身份认证。真实 Job/Pod UID、命名空间、源码/镜像、存储和签名授权检查仍必须通过。
精确对象权限需包含报告的创建一次 PUT 和 GET；缺权限时保留已完成状态并报错，
不得转为本机大文件核验或另起训练。

## 验证和边界

原生回归在远端 Mission/ZIP 不可用时仍能从缓存结算并生成报告，错误结算
SHA 或缓存篡改被拒绝，重复生成报告字节相同。控制器回归注入报告 GET 失败，
验证恢复不增加 Job、结算次数或大对象 GET，且完成前必须成功读回报告。
原有学习/审批/提交中断及证据篡改场景继续验证。

实际 #1165 的六个 Campaign 均为 `campaign_no_candidate`，300/528 次试验，
49 份认证回执，无待定试验或待发布回执。104 个自有资源已按 UID 清理，
共享物化 PVC 保留。原有节点保留标记已恢复；没有重跑六组训练。

这次代码验证与上述运行补救是不同证据：新原生报告路径尚未执行新的真实
市场研究批次。不会为了验证传输流程重花这六组研究预算。Job TTL 也不负责
删除任意 PVC、RAM 权限或节点标记，仍需原任务的云端资源清理及独立读回。
