# Native platform terminal budget bridge

This bridge is a new behavior after source export PR1328. It is not implemented or runtime-accepted by that PR.

The source must resolve one existing PlatformTransferred operation from the authenticated family/Study ledger. The readonly platform transport must independently resolve the exact tenant, imported native signature/trust, fixed Run, Task specification/revision, collection, and recorded Attempt lease/ExecutionHandle. Current Task.stopped clears its execution field, so the immutable event immediately before stop reconciliation is required to recover the admitted Job UID and fence.

The source then independently reads Kubernetes. It checks the recorded cluster/namespace/Job UID, owner Pod UID, pinned image and canonical command/configuration, and the process-tree stopped facts. Unknown deletion, a running or cancelling Pod, ambiguous attempts, conflicting identities or missing receipts cannot produce terminal evidence. These paths append no settlement and retain the entire charge.

The app owns a non-deserializable VerifiedPlatformTerminalEvidence. Its constructor is the independent PG/Kubernetes/native-result readback adapter, not a caller JSON file, boolean or aggregate trial count. It reuses mission_campaign::readback_pre_holdout_terminal_cached, mission_runner::recover_execution_report_from_cached_result and validate_native_campaign_result_binding. These existing validators bind the exact request, protocol, original native mission, actual ZIP contents, prepared collection, Replay receipts and withheld-data isolation. No parallel scientific validator is introduced.

The store adds an append-only PlatformSettled event to the original family/Study ledger. It matches the existing transfer and reservation, keeps exclusive platform ownership and never manufactures a legacy DispatchClaimed record. The event is a mechanical negative/full-charge audit. Failed, cancelled or insufficient-evidence terminal facts cannot promote science or release budget. Any future budget release requires a separately reviewed original-grant and independent known-consumption authority contract.

Mechanical negative audit remains recordable after original expiration or revocation. It acquires the original approval, family and Study guards, then samples the clock. This does not renew scientific authority or authorize another execution. Publication/readback failure must preserve the exact durable event for idempotent retry.

The readonly platform transport, independent provider stop proof and final store/app API are pending implementation. Tests will use focused source-ledger and provider/receipt fixtures only. No real cloud resources, schema migration, model fit, scientific Run, trading, risk change, resume or holdout operation is authorized by this bridge's local validation.
