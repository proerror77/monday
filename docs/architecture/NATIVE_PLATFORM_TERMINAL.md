# Native platform terminal budget audit

The source observes one existing `PlatformTransferred` operation. It grants no execution, retry, budget release or scientific promotion. Unknown resources or running processes produce no audit. The original full charge remains reserved.

The production observer is `mission dispatch audit-platform-terminal`. It requires the scientific validator build and the controlled ACK host. It never runs Cargo with private keys or starts a scientific Job. The default build rejects this command before observation.

The observer reconstructs the finalized request and its durable native reservation. It reads the existing source ledger and independently published transfer receipts. A caller cannot import a reservation, a stop boolean or a terminal JSON document as authority.

The host pins `researchctl` to its verified release signature and actual executable bytes. That prebuilt observer queries the exact tenant/request in a readonly PG transaction. Source validation binds the native signature/trust, Run, Task specification, original operation, original full debit and exact terminal ledger revision. PG heartbeats may renew authority. Provider comparison uses the actual initial `AttemptIdentityRef.launch_lease`, including its original owner and expiry.

The source then reads the original Kubernetes Job and owner Pod. It checks UID, task, attempt, fence, pinned image, command, environment, exact CPU/memory quantities and controlled identity UID/scope/mount. Every declared initializer and worker must have terminated once. Natural Complete/Failed resources remain available for this readback. Missing resources, incomplete Pod lists, deleted cancellation/timeout resources, unknown ownership or a running process yield no evidence.

Successful compute requires the actual immutable platform result receipt. The source reads every native result and ZIP from its exact signed object identity. It verifies archive paths, entries, size and hashes with the shared pure `campaign-result-validation` API. It then calls the original `readback_pre_holdout_terminal_cached` validator with the genuine finalized request and durable reservation SHA. Original model ledgers, math, trace, native prepared blocks, Replay bindings and holdout isolation remain mandatory. Aggregate worker trial counts cannot replace this validation.

`PlatformSettled` is a new append-only event in the same family and Study ledgers. It preserves exclusive platform ownership. It cannot create a legacy claim or settlement. It separately records actual compute state, scientific status, policy `charging_trials` and independently known scientific consumption. Development evidence remains `insufficient_evidence` even when the original validator proves exact consumption. Failed compute may record unknown scientific consumption. It never fabricates consumption from declared trials. The original trial, attempt, seconds and token charges remain unchanged.

Mechanical full-charge audit remains possible after original expiration or approval revocation. The store locks the original approval, Study and family before sampling the clock. This operation cannot renew scientific authority.

The private retained manifest binds the complete readonly snapshot, Job/Pod documents, native result, mission files, ZIP files, prepared-input metadata and original transfer receipt. The authenticated audit binds that manifest, exact task/attempt/fence, original Job/Pod UIDs and terminal revision. Publication retry resolves the already registered audit and verifies its complete retained file coverage. It cannot substitute newer observations or change timestamps.

Use `--retain-only` to retain the audit and return its finite publication keys. This step reports publication as pending and issues no cleanup witness. The controlled host supplies exact finite PUT/GET access for those keys. A subsequent invocation publishes the same family/Study receipts and raw observation package. Each immutable PUT requires an independent bounded GET with the same bytes and digest. Publication failure retains the original debit and audit for retry.

Observation configuration uses `monday.native_campaign_terminal_observer.v1`. It names the prebuilt observer, build/release/public trust files, native public trust, exact PG artifact readback URLs, TLS paths and finite observation publications. It contains no private signing material. The directory and files remain private. The raw package key binds the original operation and audit content hash.

After every family/Study receipt and raw object passes independent readback, the source loads the distinct private native-witness key. It signs `NativeTerminalAuditWitness` under `monday.native_terminal_audit_witness.v1`. The signature binds the exact platform request/task, Run, original operation/native evidence, published audit receipt, retained manifest, attempt/fence, Job/Pod UIDs and terminal revision. `issued_ms` comes from the original authenticated audit receipt. Retry verifies and reuses the same signature. Private bytes never enter the ledger, JSON or logs.

An unsigned durable audit cannot authorize the signing fast path. Publication retry repeats the actual released PG observer, provider stop and original scientific validation until a genuine native witness exists. After that signature exists, its original audit and complete retained package remain mandatory. This permits publication recovery after a controlled cleanup has removed provider resources.

The signed witness object is `research/native-terminal-audits/{operation_sha256}/signed-{evidence_sha256}.json`. Raw objects use `research/native-terminal-audits/{operation_sha256}/{audit_content_sha256}/{relative_name}`. The retained manifest lists file names, exact bytes and SHA256 values. Its own bytes and `terminal-audit.json` are published separately; the authenticated family receipt binds the audit document.

The controlled PG/Kubernetes cleanup consumer is separate work. Serializable HMAC metadata and a PG stopped flag do not grant cleanup authority. Natural Job/Pod garbage collection must verify the published native witness, exact PG binding and actual retained content first. No cancellation cleanup claim follows from a disappeared provider resource.

Local validation covers genuine finalized input/source assembly, exact readonly snapshot binding, original launch lease, provider process-tree stop, controlled identity, complete retained file coverage and family/Study full-charge recovery. These fixtures prove Code behavior. They do not prove a cloud Run, deployment, real scientific success, notification delivery or production cleanup.
