# Native platform terminal budget bridge

This bridge is a new behavior after source export PR1328. It is not implemented or runtime-accepted by that PR.

The source must resolve one existing PlatformTransferred operation from the authenticated family/Study ledger. The readonly platform transport must independently resolve the exact tenant, imported native signature/trust, fixed Run, Task specification/revision, collection, and recorded Attempt lease/ExecutionHandle. Current Task.stopped clears its execution field, so the immutable event immediately before stop reconciliation is required to recover the admitted Job UID and fence.

The source then independently reads Kubernetes. It checks the recorded cluster/namespace/Job UID, owner Pod UID, pinned image and canonical command/configuration, and the process-tree stopped facts. Unknown deletion, a running or cancelling Pod, ambiguous attempts, conflicting identities or missing receipts cannot produce terminal evidence. These paths append no settlement and retain the entire charge.

The app owns a non-deserializable VerifiedPlatformTerminalEvidence. Its constructor is the independent PG/Kubernetes/native-result readback adapter, not a caller JSON file, boolean or aggregate trial count. It reuses mission_campaign::readback_pre_holdout_terminal_cached, mission_runner::recover_execution_report_from_cached_result and validate_native_campaign_result_binding. These existing validators bind the exact request, protocol, original native mission, actual ZIP contents, prepared collection, Replay receipts and withheld-data isolation. No parallel scientific validator is introduced.

The store now implements an append-only PlatformSettled audit in the original family/Study ledger. It matches the existing transfer and reservation, keeps exclusive platform ownership and never manufactures a legacy DispatchClaimed or AttemptSettled record. The event separately records the actual platform compute state, scientific evidence status, policy charging_trials and optionally independently known scientific consumption. A computeSucceeded/insufficient_evidence result retains those states; it does not become a fabricated failed compute or successful science result. Policy charging_trials always equals the original declared trials. The existing conservative uncertain_trials accounting retains that full debit; it does not claim actual scientific consumption. Original attempt/seconds/token charges also remain unchanged.

The audit cannot promote science, release budget, authorize a retry or enable the legacy writer. Its historical record is serializable for authenticated ledger recovery; it is not opaque terminal authority or a caller import endpoint. The app's private independent observer will be the production caller. Any future budget release or retry bridge requires the original active grant and separately verified consumption/stop authority, not this mechanical audit or aggregate platform metrics.

Mechanical negative audit remains recordable after original expiration or revocation. It acquires the original approval, family and Study guards, then samples the clock. This does not renew scientific authority or authorize another execution. Publication/readback failure must preserve the exact durable event for idempotent retry.

The source binding, mechanical family/Study audit and its authenticated recovery are implemented and locally tested. The independent provider validator is implemented in focused fixtures. The readonly platform transport and final app observer/CLI are pending the Root snapshot source and real native ZIP validator dependency. The prior controller deleted Job and Pods before exposing terminal state, which made a fresh independent stop readback impossible. Root is changing naturally completed Jobs to retain stopped Job/Pods for this readback. Deleted cancellation/timeout resources remain unknown and produce no audit. No missing provider resource, PG stop flag or hash replaces original provider facts.

Tests use focused source-ledger and provider/receipt fixtures only. No real cloud resources, schema migration, model fit, scientific Run, trading, risk change, resume or holdout operation is authorized by this bridge's local validation.
